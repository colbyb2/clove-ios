# Clove Health Tracker

Clove is a free, open-source iOS health tracker for recording symptoms and day-to-day health information without creating an account. The app stores its working data locally and performs its charts and statistical analyses on the device.

> Clove is a tracking and reflection tool, not a medical device. Its charts, trends, and correlations do not diagnose conditions, establish causation, or replace professional medical advice.

## What Clove supports

- Daily tracking for mood, pain, energy, symptoms, medications, meals, activities, hydration, notes, weather, bowel movements, flare days, and menstrual-cycle entries
- Configurable tracking modules, symptom ordering, activity categories, hydration units, reminders, themes, and Today layout
- An optional Gentle Plans list with planned, done, later, and removed states that never counts as logged activity
- Calendar history, search, metric charts, saved comparisons, and locally calculated statistical insights
- CSV export for spreadsheet use
- Versioned JSON backup and restore for Clove data and preferences
- Recovery backups before a restore or replacement import
- No account, advertising SDK, remote analytics SDK, or developer-operated cloud sync

Availability depends on the modules a user enables. See [Product Claims and Verification](docs/PRODUCT_CLAIMS.md) for the evidence and limits behind these statements.

## Analytics: what the results mean

Clove uses deterministic calculations over the records on the device. Depending on the metric and available data, the app can show summaries, trends, distributions, and relationships between metrics. These results are not generated by artificial intelligence and do not predict future health outcomes. Cycle tracking can show an estimated next period from prior marked starts, with its limitations stated in the app.

A correlation describes an observed relationship in the recorded data. It does not prove that one factor caused another, and missing or selectively recorded days can change the result.

## Privacy and security boundary

Clove is designed to work without a Clove-operated server. Health records are stored in a SQLite database inside the app's iOS sandbox. Clove does not add database-level encryption, so device passcode and operating-system protections matter. Exported files should be treated as sensitive health information.

Read the full [Privacy Policy](PRIVACY.md).

## Backup and export

- **Clove backup (JSON):** the versioned format intended for restoring Clove data, settings, reminders, and saved analysis state.
- **CSV export:** a portable, human-readable subset intended for spreadsheets and sharing. It is not a lossless replacement for a full Clove backup.
- **Recovery backup:** created and verified before Clove replaces data during a restore or import.

Keep an independent copy of important backups. Import and restore operations can fail, and Clove does not provide cloud storage.

## Accessibility

Clove includes accessibility labels and values for many primary controls and supports system text scaling in parts of the interface. Accessibility coverage is still being improved and has not been certified against WCAG or another conformance standard. Accessibility issues are welcome in the [issue tracker](https://github.com/colbyb2/clove-ios/issues).

## Development

### Requirements

- macOS with Xcode
- iOS 17 or later deployment target
- Swift Package Manager access for dependencies

### Build

```bash
git clone https://github.com/colbyb2/clove-ios.git
cd clove-ios
open Clove.xcodeproj
```

Select the `Clove` scheme and an iOS simulator or device, then build in Xcode. The primary external dependency is [GRDB.swift](https://github.com/groue/GRDB.swift), used for local SQLite access.

### Architecture

Clove is a SwiftUI application using observable view models, repositories, and a GRDB-backed database layer.

```text
Clove/
├── App/          App lifecycle and navigation
├── Metrics/      Metric definitions and local analysis
├── Models/       Persisted and presentation models
├── Persistence/  Database setup and migrations
├── Repos/        Data-access repositories
├── Services/     Import, export, reminders, and domain services
├── ViewModels/   Screen state and application logic
└── Views/        SwiftUI screens and shared components
```

Health-data persistence should go through the repository and database layers. Schema changes require a migration. Public product or privacy claims should be updated together with [Product Claims and Verification](docs/PRODUCT_CLAIMS.md).
